# Code Review: Staged AI Tools Changes

1.
   - **Reasoning:** In `modules/home-manager/ai-tools.nix`, `enabledSkillNames` builds repository-level skill groups with `optional cfg.skills.caveman.enable cavemanSkillNames` and the same pattern for Matt Pocock and Superpowers. `optional` wraps its second argument as a single list element, so the result contains nested lists such as `[ [ "caveman" ... ] ]`, not a flat list of skill-name strings. `filterSkills` then checks `elem name enabledSkillNames`, where `name` is a string, so repository-category skills never match. Standalone skills still work because they are appended as strings. Existing tests do not assert generated skill files, so this regression can pass builds.
   - **Conclusion:** Replace the three category uses of `optional` with `optionals` or otherwise flatten the list. Add tests asserting category skills are generated by default and absent when the corresponding repo toggle is disabled.

2.
   - **Reasoning:** `mkOmpProfileFiles` writes OMP agents, commands, and skills to `${dir}/agents`, `${dir}/commands`, and `${dir}/skills`. Upstream OMP documents global locations as `~/.omp/agent/agents`, `~/.omp/agent/commands`, and `~/.omp/agent/skills`, while `.omp/commands` / `.omp/skills` are project-local locations. Because Home Manager writes these under the user's home directory, generated files in `~/.omp/skills` are unlikely to be discovered as global skills when running `omp` from arbitrary projects. Config and MCP files are already placed under `${dir}/agent`, which makes the neighboring asset placement inconsistent.
   - **Conclusion:** Write generated OMP user assets under `${dir}/agent/agents`, `${dir}/agent/commands`, and `${dir}/agent/skills`. Add tests that assert OMP skill and command files exist under `.omp/agent/...`.

3.
   - **Reasoning:** The Matt Pocock and Superpowers integrations import only each `SKILL.md`. Several imported skills explicitly reference sibling files: Matt's `prototype` links to `LOGIC.md` and `UI.md`; `tdd` links to `tests.md`, `mocking.md`, `deep-modules.md`, and related files; `grill-with-docs` links to `CONTEXT-FORMAT.md` and `ADR-FORMAT.md`; Superpowers skills also include local supporting references. Those supporting files are not copied into generated skill directories, so agents will be instructed to read files that do not exist. Also, the Matt README's Engineering list includes `setup-matt-pocock-skills`, which is omitted even though other Matt skills rely on its per-repo setup model.
   - **Conclusion:** Represent external skills as directories, not only `SKILL.md` text. Copy each selected skill directory, including sibling markdown/scripts, or add an `extraFiles` mechanism per skill. Include `setup-matt-pocock-skills` if the target is the README's engineering/productivity set, or explicitly document any deliberate omission.

4.
   - **Reasoning:** Several new OMP options are exposed but not honored. `tools.omp.package` is defined, but `lib/omp.nix::mkOmpWrapper` always uses `llmAgents.omp` in both `runtimeInputs` and `exec`, so package overrides are ignored. `tools.omp.mcp.memoryDir` is defined, but `legacyOmpProfile.mcp.memoryDir` is hardcoded to `${cfg.profileName}-omp`. Per-profile `settings` and `modelSettings` are also defined, but `mkOmpConfigYaml` and `mkOmpModelsYaml` merge only top-level `cfg.tools.omp.settings` / `modelSettings`, not `profile.settings` / `profile.modelSettings`.
   - **Conclusion:** Thread these options through the profile model and wrapper. Use the configured OMP package, honor `cfg.tools.omp.mcp.memoryDir`, and merge per-profile settings/model settings after global settings.

5.
   - **Reasoning:** `mkOmpWrapper` renders profile environment variables as `export ${k}="${envVars.${k}}"`. Values containing quotes, command substitutions, backticks, newlines, or other shell metacharacters can break the wrapper or trigger shell expansion at runtime. This is especially relevant because the option description recommends using `env` for API keys and provider credentials. Existing tests only cover a simple `test-key`, so they do not catch quoting edge cases.
   - **Conclusion:** Escape environment values with shell-safe quoting, such as `lib.escapeShellArg`, and validate environment variable names before emitting export statements.
